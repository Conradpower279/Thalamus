# app/ — Flutter application (placeholder)

The phase-1 mobile app: point the camera at a fish while swimming or diving, get
a species identification in real time, and log the sighting. Nothing here yet —
this directory is a placeholder so the model export path has a defined
destination.

## What the app consumes

Two files, both produced by the export pipeline:

| File | Produced by | Purpose |
| --- | --- | --- |
| `fish_classifier_float16.tflite` | `export/export_tflite.py` | The classifier itself |
| `classes.json` | `scripts/fish_classifier_train.py` | Maps output index → species name |

Both land in `export/output/`. Copy them into the Flutter app's assets:

```
app/assets/models/fish_classifier.tflite
app/assets/models/classes.json
```

and declare them in `pubspec.yaml`:

```yaml
flutter:
  assets:
    - assets/models/fish_classifier.tflite
    - assets/models/classes.json
```

## The inference contract

Getting this wrong is the single most common reason a model that scored well in
Python returns nonsense on a phone. The exported graph expects:

- **Input shape** `[1, 3, 224, 224]` in the ONNX graph. The TFLite conversion
  rewrites this to NHWC, so the TFLite model takes `[1, 224, 224, 3]`. Confirm
  against the converted model rather than assuming.
- **RGB channel order.** Not BGR. Camera plugins vary — check what yours emits.
- **Float32 in the range 0..1**, then normalised with the ImageNet statistics:
  - mean `[0.485, 0.456, 0.406]`
  - std `[0.229, 0.224, 0.225]`
  - i.e. `pixel = (pixel / 255.0 - mean) / std`, per channel.
- **Resize to a square**, matching `img_size` in `configs/default.yaml`. The
  training pipeline uses a plain resize that does not preserve aspect ratio, so
  the app must squash rather than letterbox — matching training is what matters,
  not which is nicer.
- **Output** is a `[1, num_classes]` vector of raw **logits**, not probabilities.
  Apply softmax in the app if you want a confidence score.

If you use an int8 model, the input and output tensors are quantized and carry
scale/zero-point values; read them from the interpreter rather than hardcoding.

## Two things to design for before shipping

**The model cannot say "I don't know."** Softmax always sums to 1, so a camera
pointed at kelp, sand, a diver's fin, or a species outside the training set
still yields a confident-looking prediction. Suppress low-confidence
predictions behind a threshold — and pick the threshold by measuring against
real negative footage, not by guessing. Without this the app will confidently
misidentify empty water, which is exactly the behaviour that destroys user
trust.

**Class indices are positional.** `classes.json` is generated by sorting species
directory names. Adding one species later re-sorts the list and shifts every
index after it. Always ship `classes.json` together with the `.tflite` file it
was generated with, and never hardcode the species list in Dart.

## Suggested starting points

- `tflite_flutter` for inference, `camera` for the frame stream.
- Run inference on a background isolate; decoding and preprocessing frames on
  the UI thread will drop the preview to single-digit FPS.
- Throttle to a few inferences per second rather than running on every frame —
  it is plenty for species ID and saves a lot of battery underwater, where you
  cannot charge.
- Log sightings with timestamp and GPS-at-surface; underwater there is no fix,
  so record position when the phone next sees the sky.
